# ADR-0008. Вычисления на этапе компиляции и метапрограммирование

- **Статус:** предлагается
- **Дата:** 2026-11-04
- **Связано:** [ADR-0004](0004-types-and-polymorphism.md), [ADR-0006](0006-compiler-architecture.md); [ARCHITECTURE_REVIEW.md](../ARCHITECTURE_REVIEW.md) §3.8; вопрос Q-27

## Проблема

Вычисления на этапе компиляции и генерация кода нужны для констант, таблиц, сериализации, `derive`. Варианты сильно различаются по сложности и по влиянию на проверку типов, IDE и время сборки.

## Возможные варианты

1. **`const fun`** — ограниченное подмножество языка, вычисляемое интерпретатором среднего IR (Rust).
2. **`comptime`** — весь язык на этапе компиляции, типы как значения (Zig).
3. **Процедурные макросы** (Rust) или плагины компилятора (Kotlin).
4. **Статическая рефлексия** — чтение структуры типов на этапе компиляции.
5. **Встроенный `derive`** для фиксированного набора трейтов.

## Рекомендуемое решение

- **В 1.0 — варианты 1 и 5.** Варианты 3 и 4 — решение после этапа 4, по собранным сценариям (Q-27). Вариант 2 не вводится.
- **`const fun`:** без I/O, без недетерминированности, с лимитом шагов. Вычисляется интерпретатором KIR с раскладкой данных целевой платформы (а не хоста).
- **Константные параметры обобщений** — только простые значения (целые, `Bool`, `Char`); выражения в типах — не в 1.0.
- **`derive`** встроен в компилятор для равенства, порядка, хеша, отладочного вывода, клонирования, `Copy` и — после стабилизации трейтов сериализации — для сериализации. Запись — атрибут `@derive(Eq, Hash, Clone, …)` ([ADR-0010](0010-syntax.md)).

## Причины выбора

- Интерпретатор KIR нужен и так: для проверки неопределённого поведения и для дифференциального тестирования. CTFE получается почти даром.
- `comptime` подрывает проверенные обобщения и поддержку IDE: ошибки обобщённого кода всплывают только при подстановке.
- Макросы — значительная сложность для компилятора, IDE и безопасности сборки. С `derive` можно выпустить полезный язык и без них.

## Последствия

- Набор `derive` фиксирован; пользовательские генераторы кода появятся позже.
- Kenox.JSON появляется после `derive` для сериализации.
- Сборочные скрипты (аналог `build.rs` в Cargo) — отдельный вопрос, вне 1.0.

## Риски

- **Пользователи упрутся в отсутствие макросов** для DSL и шаблонного кода. Снижение: собирать конкретные сценарии и решать их точечно; выбор механизма — по данным.

## Статус и условия пересмотра

Предлагается. Пересмотр — после этапа 4, по накопленным сценариям.
