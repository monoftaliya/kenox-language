# KENOX — эскиз синтаксиса

> Версия 0.2 · 5 ноября 2026 · Статус: утверждён как основа спецификации (05.11.2026, [ADR-0010](ADR/0010-syntax.md)); точные правила — в спецификации ядра (шаг 0.3)
>
> Это не грамматика и не спецификация: точные правила — шаг 0.3. Документ фиксирует соглашения, по которым написан [корпус примеров](../examples/README.md), чтобы его можно было проверить на согласованность. Найденные при написании проблемы и принятые по ним решения — в [CORPUS_REVIEW.md](CORPUS_REVIEW.md) (ссылки вида Р-N).

## Цели

- **Читаемость:** код читается сверху вниз без знания тонкостей языка.
- **Лаконичность без магии:** всё, что изменяет данные вызывающего или опасно (`unsafe`, граница с C), видно в коде.
- **Системная точность:** размеры типов, раскладка, выделение памяти и владение не скрываются.
- **Узнаваемость:** Kotlin — отправная точка, но не образец для копирования. Отличия — в разделе 20.

## 1. Лексика

- Комментарии: `//`, `/* … */` (могут быть вложенными), документирующие `///`.
- Идентификаторы — Unicode с нормализацией NFC. Стиль: `camelCase` — функции и переменные, `PascalCase` — типы и варианты, `SCREAMING_CASE` — константы.
- Точка с запятой не нужна: перевод строки завершает инструкцию, если выражение закончено. `;` допустима как разделитель нескольких инструкций в одной строке.
- Числа: `42`, `1_000_000`, `0xFF`, `0b1010`, `0o755`, `3.14`, `1e-9`. Тип литерала выводится из контекста; по умолчанию — `Int` и `Float64`.
- Строки: `"…"` с интерполяцией `{выражение}` и форматом `{x:>10}`, `{x:.2}`. Литеральные фигурные скобки — `{{` и `}}`. Сырые строки `r"…"` — без экранирования и интерполяции. Многострочные — `"""…"""`.
- Символы: `'a'`, `'\n'`, `'\u{1F600}'`.
- Ключевые слова — жёсткие; имя, совпадающее с ключевым словом, пишется в обратных кавычках: `` `type` `` (Q-42).
- Битовые операции: `&`, `|`, `^`, `~`, `<<`, `>>` (Q-43).
- У многострочной строки отступ закрывающих `"""` убирается из каждой строки при компиляции (Q-44).
- Строка, начинающаяся с `.`, продолжает выражение (цепочка методов), кроме уровня веток `match`, где `.Вариант` начинает новую ветку (Q-45).
- Точные правила — [глава 1 спецификации](../spec/01-lexical.md).

## 2. Привязки и типы

```kenox
val name = "KENOX"            // неизменяемая привязка; тип выводится
var count: Int = 0            // изменяемая привязка
const MAX_USERS: Int = 1_000
type UserMap = Map<UserId, User>
```

- Встроенные типы: `Int8`…`Int64`, `UInt8`…`UInt64`, `Int` (= `Int64`; тип по умолчанию для чисел, длин и индексов), `ISize`/`USize` (размер указателя — для FFI и низкоуровневой памяти), `Float32`, `Float64`, `Bool`, `Char`, `Unit`, `Never`.
- Неявных преобразований нет. Расширение — `x.toInt64()` (всегда успешно); сужение — `x.toInt32()` (ловушка, если значение не помещается) или `x.toInt32OrNull()`; усечение — `x.truncateToUInt8()`.
- Переполнение — ловушка во всех профилях; явные операции — `wrappingAdd`, `saturatingAdd`, `checkedAdd` ([ADR-0009](ADR/0009-base-types-null-safety.md)).
- Строки: `String` — владеющая UTF-8. **Строковый литерал имеет тип `String`** со статическим представлением: без выделения памяти, без освобождения; при первом изменении содержимое копируется в кучу (Р-4). `str` — заимствованное представление текста: для параметров и срезов. `String` передаётся туда, где ожидается `str`, без копирования.
- Пути: `Path` — путь в кодировке ОС. Функции файловой системы принимают любой «путеподобный» тип (`str`, `String`, `Path`).

## 3. Функции и режимы параметров

```kenox
fun area(w: Float64, h: Float64): Float64 = w * h

fun greet(name: str, greeting: str = "Привет") {
    println("{greeting}, {name}!")
}
```

| Объявление параметра | Смысл | На месте вызова |
|---|---|---|
| `x: T` | неизменяемое заимствование (по умолчанию) | `f(x)` |
| `inout x: T` | исключительное изменяемое заимствование | `f(&x)` — изменение видно |
| `consume x: T` | передача владения | `f(x)` или `f(consume x)` — после вызова `x` недоступна; пометка необязательна (Q-39) |

- Значения `Copy`-типов передаются копией в любом режиме.
- Получатель метода с `inout self` не помечается, но переменная должна быть `var`: `list.push(x)`.
- Именованные аргументы и значения по умолчанию: `connect("db.local", port = 5432)`. Перегрузки функций по типам нет.
- Функция без возврата управления имеет тип `Never`: `fun fail(msg: str): Never`.
- Функция в теле типа без параметра `self` — статическая: `Point.origin()`.

**Результат-заимствование.** Функция может вернуть заимствование:
- представления (`str`, `Slice<T>`, итераторы) — по типу;
- элемент обобщённого типа — с пометкой `ref T` (только чтение) или `inout T` (изменяемая проекция) (Р-12).

Источник заимствования выводится: у метода — `self`; у функции — единственный заимствованный параметр. В остальных случаях нужна аннотация `@borrows(a, b)` (Q-18).

## 4. Структуры

```kenox
@derive(Copy, Show)
struct Point {
    x: Float64
    y: Float64

    fun origin(): Point = Point(x = 0.0, y = 0.0)
    fun length(self): Float64 = (self.x * self.x + self.y * self.y).sqrt()
    fun moveBy(inout self, dx: Float64) { self.x += dx }
}

val p = Point(x = 1.0, y = 2.0)     // поэлементный конструктор
val q = Point(3.0, 4.0)             // позиционно
val r = p.with(y = 5.0)             // копия с изменённым полем
struct UserId(Int)                  // обёртка; поле — id.0
struct Size { w: Int, h: Int }      // поля в одну строку — через запятую
```

- Поля и методы — в теле типа. Доступ к полям — только через `self.`.
- Поэлементный конструктор доступен там, где видны все поля. Приватное поле скрывает конструктор — так строятся типы с инвариантами (проверяющая статическая функция).

## 5. Перечисления

```kenox
enum Shape {
    Circle(radius: Float64)
    Rect(width: Float64, height: Float64)
    Empty

    fun area(self): Float64 = match self {
        .Circle(r) -> Float64.PI * r * r

    }
}

val s = Shape.Circle(radius = 1.0)
val t: Shape = .Rect(width = 2.0, height = 3.0)   // точка в начале: тип известен из контекста

@repr(Int32)
enum Level { Low = 1, High = 2 }                   // C-совместимое перечисление
```

Варианты разделяются переводом строки или запятой.

## 6. Трейты, расширения, делегирование

```kenox
trait Shape {
    fun area(self): Float64
    fun describe(self): String = "фигура площадью {self.area()}"   // по умолчанию
}

extend Circle: Shape {                  // реализация трейта
    fun area(self): Float64 = Float64.PI * self.radius * self.radius
}

extend str {                            // методы-расширения чужого типа
    fun isBlank(self): Bool = self.trim().isEmpty()
}

extend<L: Log> Numbered<L>: Log by self.inner {   // делегирование
    fun write(inout self, line: str) { … }
}
```

- `extend Тип { … }` — методы-расширения; `extend Тип: Трейт { … }` — реализация трейта. Это одна конструкция для всего, что добавляется к типу снаружи.
- Делегирование `by self.поле`: во вложенный объект пересылаются только **обязательные** методы трейта, не реализованные явно. Методы по умолчанию вызываются на самом объекте и видят его переопределения (Р-8).
- Ассоциированные типы (`type Item`), статические функции (`fun zero(): Self`), `Self`.
- Порядок разрешения методов: собственные методы типа → методы трейтов в области видимости → расширения.
- Динамическая диспетчеризация — `Box<dyn Shape>`. Трейт с методами, имеющими собственные параметры-типы, с `dyn` несовместим.
- Автоматические реализации: `@derive(Eq, Hash, Order, Clone, Copy, Show, Default)`. Интерполяция `{x}` использует `Show`.

## 7. Обобщения

```kenox
fun largest<T: Order>(items: Slice<T>): ref T? { … }
fun printAll<T>(items: Slice<T>) where T: Show { … }
struct Stack<T> { items: List<T> }
fun dot<const N: Int>(a: Array<Float32, N>, b: Array<Float32, N>): Float32 { … }
fun evens(limit: Int): some Iterator<Int> = (0..<limit).filter { it % 2 == 0 }
```

- Мономорфизация; ограничения трейтами; `where`.
- `Iterator<T>` — сокращение для `Iterator` с `Item = T`.
- `some Трейт` — непрозрачный тип результата: конкретный тип скрыт, но известен компилятору (Р-11).
- Константные параметры — только простые значения; выражений в типах (`Array<T, R * C>`) в 1.0 нет ([ADR-0008](ADR/0008-compile-time-and-metaprogramming.md), Р-14).

## 8. Выражения и управление потоком

```kenox
val kind = if n < 0 { "минус" } else if n == 0 { "ноль" } else { "плюс" }
for i in 0..<10 { … }          // полуоткрытый диапазон
for i in 1..=10 { … }          // закрытый диапазон
while queue.isNotEmpty() { … }
loop { if done() { break } }
val area = do {                // блок-выражение
    val w = 3
    w * 4
}
val found = "go" in languages  // принадлежность
```

- Скобки вокруг условий не нужны; фигурные скобки обязательны.
- `if`, `match` и `do { }` — выражения.
- `{ … }` в позиции выражения — замыкание. Исключение — тело ветки `match` после `->`: там фигурные скобки образуют блок, как в Kotlin. Отдельный блок-выражение пишется как `do { … }` (Р-2).
- Диапазонов `a..b` без уточнения нет: только `..<` и `..=`.
- Присваивание — инструкция, а не выражение. `?:` связывает сильнее сравнений и диапазонов. Замыкание в условии `if`/`while`, после `match` и после `in` в `for` пишется в скобках: `if xs.any({ it > 0 }) { … }`. Аргументы типа в выражении (`Arena<Expr>()`) распознаются пробным разбором. Точные правила — [глава 2 спецификации](../spec/02-syntax.md).

## 9. Сопоставление с образцом

```kenox
match token {
    .Number(n) if n > 100 -> "большое число"
    .Number(_) -> "число"
    .Plus | .Minus -> "оператор"
    _ -> "прочее"
}
if shape is .Circle(r) && r > 1.0 { … }     // is: проверка образца с привязками
val (lo, hi) = bounds                         // неопровержимый разбор
val Point(x, y) = point
```

- Образцы: литералы, `_`, привязки, варианты `.V(…)`, кортежи, структуры `Point(x, y)`, диапазоны `0..=9`, альтернативы `|`, условия `if`.
- Привязки после `is` видны в той части условия, где образец гарантированно совпал, и в теле `if`.
- **Режим привязок** — как у подвыражения (Р-17): сопоставление со своим (владеемым) значением перемещает части; с заимствованным — заимствует; с `inout`-местом — даёт `inout`-привязки. `match ref x` заимствует даже своё значение.
- Компилятор проверяет полноту.
- Одиночное имя в образце — всегда новая привязка; константы сравниваются по полному имени (`Int.MAX`) или через условие ветки. Совпадение имени привязки с константой — предупреждение.

## 10. Null safety

```kenox
val nick: String? = null
val len = nick?.len() ?: 0
if val n = nick { println(n) }
while val job = queue.popFirst() { … }
val user = findUser(id) ?: return Err(.NotFound(id))
val sure = nick.unwrap()                     // паника, если null
```

- `T?` — сахар для `Option<T>`; `null` — пустое значение; значение `T` подставляется в `T?` автоматически. Вложенные `T??` различимы.
- Умных приведений (smart cast) в 0.x нет: используйте `if val`.
- `if inout x = …` и `inout x = …` — распаковка и привязка изменяемой проекции.

## 11. Ошибки

```kenox
fun loadPort(path: str): Result<Int, ConfigError> {
    val text = try fs.readText(path)         // try — передать ошибку выше
    return Ok(try text.trim().parseInt())
}
```

- `try выражение` — если результат — ошибка (или `null` в функции, возвращающей `T?`), функция возвращает её, при необходимости преобразуя через трейт `From` (Р-1).
- `Ok()` — то же, что `Ok(Unit)`. `Err(.Variant(…))` — точка в начале работает, когда тип ошибки известен.
- Для приложений — `AnyError` с контекстом: `try fs.readText(path).context("чтение {path}")`. `main` может возвращать `Result<Unit, AnyError>`.
- `panic("…")`, `assert(cond, "…")`, `unreachable("…")` — для ошибок программиста.

## 12. Замыкания

```kenox
val evens = numbers.filter { it % 2 == 0 }
val total = items.fold(0) { acc, item -> acc + item.price }
var count = 0
items.forEach { count += 1 }            // невыходящее замыкание заимствует `count`

fun makeCounter(): escaping () -> Int {
    var n = 0
    return {                            // выходящее замыкание забирает `n`
        n += 1
        n
    }
}
```

- Параметр-функция `(A) -> B` — невыходящий: замыкание нельзя сохранить, но оно может заимствовать локальные переменные.
- `escaping (A) -> B` — замыкание-значение, которое можно вернуть или сохранить. Захваченные переменные перемещаются в него (Р-7).
- Параметры замыкания получают режим из типа параметра-функции: в `(inout T) -> Unit` изменять можно и `it`.
- Последний аргумент-замыкание выносится за скобки: `list.sortBy { it.priority }`.

## 13. Коллекции и литералы

```kenox
val xs = [1, 2, 3]                         // List<Int>
val ages = ["Анна": 31, "Борис": 27]        // Map<String, Int>
val empty: Map<String, Int> = [:]
val tags: Set<String> = ["fast", "safe"]   // Set — по ожидаемому типу
val buf: Array<UInt8, 4> = [0, 0, 0, 0]    // массив фиксированной длины
for x in xs { … }                          // обход заимствует коллекцию
for inout x in &ys { x *= 2 }              // изменяемый обход
for x in consume zs { … }                  // обход с передачей владения элементами
```

- Индексация `xs[i]` проверяет границы (паника при выходе); `xs.get(i)` возвращает `T?`.
- Взять элемент не-`Copy` типа в переменную можно только явным заимствованием `val e = ref xs[i]`, клонированием или удаляющим методом (Р-16).
- `Slice<T>` — представление непрерывной последовательности: `xs.slice(1..<3)`.

## 14. Память

```kenox
val b = a                          // перемещение (для не-Copy): `a` больше недоступна
val c = b.clone()                  // явная копия
val alias = ref c                  // явное заимствование в локальной переменной
drop(consume c)                    // `consume x` — необязательная явная пометка перемещения

val cfg = Shared(Config.load())    // разделяемое владение, атомарный счётчик
val other = cfg.share()            // ещё один владелец — явно (Q-08)
val weak = cfg.downgrade()         // Weak; weak.upgrade() возвращает Shared<T>?
val local = LocalShared(Node())    // для одного потока: неатомарный счётчик

val hits = Cell(0); hits.set(hits.get() + 1)        // Copy-значения
val names = Cell(List<String>()); names.update { it.push("x") }
val total = Mutex(0); total.lock { it += 1 }       // доступ только внутри замыкания

var arena = Arena<Node>()
val id: Id<Node> = arena.add(Node())
unsafe { … }
```

- Использование своего (не-`Copy`) значения в позиции владения — присваивание, `consume`-параметр, возврат, запись в поле или коллекцию — перемещает его. Повторное использование — ошибка компиляции. Пометка `consume x` на месте вызова разрешена, но не обязательна (Q-39).
- **Невыходящие типы** (Q-40). Тип, содержащий заимствование, — невыходящий; это свойство выводится, как `Send`. Таковы представления (`str`, `Slice<T>`), итераторы с заимствующими замыканиями, `List<str>`, структуры с полем-представлением. Невыходящее значение можно держать в локальной переменной, передавать и возвращать с зависимостью от источника, но нельзя сохранить в поле обычной структуры, `Shared`, глобальной переменной или выходящем замыкании. Пример: `val words = text.split(' ').toList()` даёт `List<str>`, который можно использовать, пока жив `text`.
- `Cell` проверяет повторный вход в `update` во время выполнения (паника, а не неопределённое поведение). `Cell` не `Sync`.
- Деструктор: `extend T: Drop { fun drop(inout self) { … } }`.

## 16. Модули, видимость, пакеты

- Файл — модуль. Имя модуля — путь файла относительно `src/`: `src/net/http.kenox` → `net.http`.
- `import std.fs`, `import std.collections.{Map, Set}`, `import model.item.Item`; `pub import` — реэкспорт.
- Видимость: по умолчанию — внутри пакета; `pub` — публичный API пакета; `private` — только внутри файла.
- Корневой модуль (`src/main.kenox` или `src/lib.kenox`) модули своего пакета не импортируют. Имена из других модулей — только через импорт: `std.fs.readText(…)` без `import std.fs` не пишется. Без импорта доступны встроенные типы и прелюдия (`String`, `List`, `Result`, `println` и другие). Перегрузки нет; параметр и локальная переменная не повторяют видимое имя; метод трейта вызывается, когда трейт импортирован или входит в прелюдию. Точные правила — [глава 3 спецификации](../spec/03-names.md).
- `kenox.toml`:

```toml
[package]
name = "inventory"
version = "0.1.0"
kind = "bin"            # bin | lib | staticlib | dylib

[dependencies]
textstats = { path = "../textstats" }
```

## 18. Взаимодействие с C

```kenox
extern "C" {
    fun strlen(s: RawPtr<CChar>): CSize
    fun qsort(base: RawMutPtr<CVoid>, n: CSize, size: CSize,
              cmp: extern "C" fun(RawPtr<CVoid>, RawPtr<CVoid>) -> CInt)
}

@repr(C)
struct Rect { width: CDouble, height: CDouble }

@export("kx_add")
extern "C" fun add(a: CInt, b: CInt): CInt = a + b
```

- Вызов `extern`-функции — только в `unsafe`.
- `RawPtr<T>` (только чтение) и `RawMutPtr<T>` — сырые указатели; `addressOf(x)` и `addressOf(&x)` из `std.mem` — получить указатель (в `unsafe`-контексте использования).
- Строки: `CString.from(s)`, `CStr.fromPtr(p)`, `withCString(s) { p -> … }`.
- Функциональный тип в объявлении — `(A) -> B`; результат функции — после `:`.

## 19. Зарезервировано

`async`, `await` (1.1), `class` (после 1.0), `actor`, `macro`, `yield`.

## 20. Чем KENOX отличается от Kotlin и Rust

| Конструкция | Kotlin | Rust | KENOX |
|---|---|---|---|
| Условие | `if (x > 0)` | `if x > 0` | `if x > 0` |
| Сопоставление | `when (x) { … -> }` | `match x { … => }` | `match x { … -> }`, варианты `.V(…)` |
| Проверка образца | `is Type` | `if let`, `matches!` | `x is .V(a)` с привязками |
| Строковый шаблон | `"$x ${y}"` | `format!("{x}")` | `"{x}"` |
| Диапазоны | `0..n` (включая), `0 until n` | `0..n` (исключая), `0..=n` | только `0..<n` и `0..=n` |
| Передача ошибки | исключения | `expr?` | `try expr` |
| Безопасный вызов | `x?.y`, `?:` | — | `x?.y`, `?:` |
| Параметры | ссылки | `&T`, `&mut T`, `T` | режимы: по умолчанию заимствование, `inout` (`&x` при вызове), `consume` |
| Методы чужих типов | `fun String.f()` | трейт-расширение | `extend String { … }` |
| Реализация интерфейса | `class A : I` | `impl I for A` | `extend A: I { … }` |
| Делегирование | `by` | — | `by self.поле` (пересылаются только обязательные методы) |
| Блок-выражение | `run { }` | `{ }` | `do { }` |
| Доступ к полям в методе | неявный `this` | `self.` | `self.` |
| Null | `null`, `T?` | `Option<T>` | `null`, `T?` = `Option<T>` |
| Непрозрачный тип | — | `impl Trait` | `some Trait` |
