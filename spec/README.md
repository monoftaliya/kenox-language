# Спецификация ядра KENOX

> Версия 0.1-черновик · 5 ноября 2026 · Этап 0, шаг 0.3 · Главы появляются по одной, каждая — отдельным pull request

## Назначение

Спецификация — нормативное описание ядра языка KENOX версии 0.1 (MVP). Компилятор, тесты и документация сверяются с ней.

Исходные материалы спецификации — [эскиз синтаксиса](../docs/SYNTAX_SKETCH.md), [решения (ADR)](../docs/ADR/README.md) и [корпус примеров](../examples/README.md). При расхождении действует спецификация: эскиз и примеры исправляются в том же pull request.

## Объём

- **Главы 1–2 (лексика и синтаксис)** описывают весь язык эскиза: каждый пример корпуса должен разбираться.
- **Остальные главы (смысл программ)** описывают только ядро 0.1 — состав из [ARCHITECTURE.md](../docs/ARCHITECTURE.md) §11. Конструкции за его пределами (замыкания, `dyn`, `Shared`, потоки и другие) помечаются как «вне ядра 0.1» и описываются на следующих этапах.

## Как читать

**[spec.rule.id]** Нормативное правило — абзац или пункт списка, который начинается с идентификатора в квадратных скобках, выделенного полужирным, как этот. Всё остальное — примечания, обоснования и примеры — поясняет правила, но не добавляет новых.

**[spec.rule.stable]** Идентификатор правила стабилен: на него ссылаются тесты (шаг 0.5), диагностика компилятора и другие правила — в квадратных скобках, например [lex.ident.syntax]. Правило можно уточнять; удалённый идентификатор не используется повторно для другого смысла.

**[spec.terms]** «Ошибка» означает ошибку компиляции: программа не принимается. «Предупреждение» не мешает компиляции. «Должен» и «не может» — обязательные требования к программе или компилятору.

Пометки в примерах — как в корпусе:

```kenox
val count = 0          // ✓ допустимо
// ✗ [lex.ident.syntax] val 1x = 0 — идентификатор не может начинаться с цифры
```

Каждый пример с ✗ станет отрицательным тестом с ожидаемой ошибкой, каждый пример с ✓ — положительным.

## Грамматика

Грамматика записана в расширенной форме Бэкуса — Наура (EBNF):

| Запись | Значение |
|---|---|
| `Имя = … ;` | определение |
| `"if"`, `'"'` | символы или слово буквально; одинарные кавычки — когда внутри есть `"` |
| `A B` | A, затем B |
| `A \| B` | A или B |
| `[ A ]` | A необязательно |
| `{ A }` | A повторяется ноль или более раз |
| `( A )` | группировка |
| `'a' .. 'z'` | любой символ из диапазона |
| `U+000A` | символ с указанным кодом |
| `? текст ?` | множество символов, заданное словами (например, ? XID_Start ?) |
| `A - B` | A, кроме B |
| `(* … *)` | комментарий |

Лексические правила (из чего состоят лексемы) названы ЗАГЛАВНЫМИ_БУКВАМИ, синтаксические (как из лексем строится программа) — СловамиСЗаглавной. Корень лексической грамматики — `INPUT`.

`cargo test` проверяет грамматику: каждое использованное правило определено ровно один раз, и каждое определённое правило где-то используется.
